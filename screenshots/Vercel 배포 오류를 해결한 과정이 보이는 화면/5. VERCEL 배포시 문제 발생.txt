VERCEL 배포시 문제 발생 risk_assessment.py의 원래 역할 구분 후 처리

좋은 질문이에요. 정리해서 설명드릴게요.

**risk_assessment.py의 원래 역할**
이 파일은 나이·수축기혈압(SBP)·이완기혈압(DBP)·혈당 값을 받아서 위험도 점수를 계산하고 고위험군/위험군/안정군으로 분류하는 **순수 로직(비즈니스 로직) 모듈**이에요. 함수들이 들어있을 뿐, 웹 요청(HTTP request)을 직접 받아서 처리하도록 만들어진 파일이 아니었을 가능성이 높습니다. 즉 "계산기" 역할이지 "웹 서버" 역할이 아니었던 거죠.

**왜 Vercel이 진입점을 못 찾는가**
Vercel의 Python 런타임은 아무 파일이나 서버리스 함수로 인식하지 않아요. 정해진 규칙이 있습니다:

- 파일 이름이 `app.py`, `index.py`, `server.py`, `main.py`, `wsgi.py`, `asgi.py` 중 하나여야 하고
- 프로젝트 루트, 또는 `api/`, `src/`, `app/` 폴더 안에 있어야 하며
- 그 파일 안에 Flask/FastAPI의 `app` 객체(또는 그에 준하는 WSGI/ASGI 앱, 혹은 `BaseHTTPRequestHandler` 클래스)가 정의돼 있어야 합니다.

`risk_assessment.py`라는 이름 자체가 이 목록에 없고, 아마 그 안에 웹 요청을 처리하는 `app` 객체도 없었을 거예요. 그러니 Vercel 입장에서는 "이 파일을 요청이 들어왔을 때 어디에 연결해야 하지?"를 알 수 없어서 진입점을 못 찾는다고 나온 겁니다.

**왜 pyproject.toml을 새로 만들라고 하는가**
Vercel이 최근 Python 빌드 방식을 `uv` + `pyproject.toml` 기반으로 바꿨어요. 여기엔 두 가지 용도가 있어요:
1. Python 버전 지정 (`.python-version`이나 pyproject.toml에서 버전을 안 정하면 기본값 사용)
2. 표준 이름이 아닌 파일을 진입점으로 쓰고 싶을 때, `pyproject.toml`에 `[tool.vercel.entrypoint]`로 "이 파일이 진입점이야"라고 명시적으로 알려주는 용도

즉 지금 나온 안내는 "`risk_assessment.py`를 억지로 진입점으로 쓰려면 pyproject.toml에서 지정해라"는 뜻이지만, 이 방식보다는 **아예 별도의 진입점 파일을 새로 만드는 게 더 깔끔**합니다.

**추천하는 구조**
```
api/index.py   ← 새로 만듦. Flask app 객체 + 라우트 정의 (진짜 웹 요청 처리)
risk_assessment.py  ← 그대로 둠. api/index.py에서 import해서 점수 계산 로직만 재사용
```

`api/index.py`가 요청을 받아서 `risk_assessment.py`의 함수를 호출하고, AI API까지 붙여서 결과를 JSON으로 돌려주는 구조로 가면 pyproject.toml에 억지로 entrypoint를 지정할 필요 없이 Vercel이 자동으로 `api/index.py`를 인식합니다.

## 왜 pyproject.toml 억지 지정은 피해야 하나

pyproject.toml로 `risk_assessment.py`를 진입점 삼는 건 **"계산기 모듈에 억지로 웹 서버 옷을 입히는"** 방식이에요. 지금 당장은 배포가 되겠지만:

- **역할이 뒤섞임** → 나중에 위험도 로직 하나 고치려다 웹 처리 코드까지 건드리게 됨
- **테스트 어려움** → 계산 로직만 따로 검증하기 힘들어짐
- **확장 시 붕괴** → 기능이 늘어나면 파일 하나가 거대해져서 유지보수 불가

사업화하려면 **기능이 계속 추가**될 텐데, 이 구조는 그때 발목을 잡습니다.

## 실제 코드 흐름 예시

**`risk_assessment.py`** (기존 그대로, 계산 로직만)
```python
def assess_risk(age, sbp, dbp, sugar):
    """위험도를 계산해서 분류만 돌려주는 순수 함수"""
    score = 0
    if sbp >= 140 or dbp >= 90:
        score += 2
    if sugar >= 126:
        score += 2
    if age >= 65:
        score += 1

    if score >= 4:
        return "고위험군"
    elif score >= 2:
        return "위험군"
    else:
        return "안정군"
```

**`api/index.py`** (웹 진입점 — 서빙 담당)
```python
from http.server import BaseHTTPRequestHandler
import json, os
import google.generativeai as genai
from risk_assessment import assess_risk   # ← 계산 로직 import!

class handler(BaseHTTPRequestHandler):
    def do_POST(self):
        try:
            length = int(self.headers['Content-Length'])
            data = json.loads(self.rfile.read(length))

            # 1. 계산은 risk_assessment.py에 위임
            risk_level = assess_risk(
                data['age'], data['sbp'], data['dbp'], data['sugar']
            )

            # 2. AI 안내문 생성 (index.py의 역할)
            genai.configure(api_key=os.environ.get('GEMINI_API_KEY'))
            model = genai.GenerativeModel('gemini-1.5-flash')
            prompt = f"위험도 분류가 '{risk_level}'인 사용자에게..."
            result = model.generate_content(prompt).text

            # 3. 응답
            self._send(200, {"risk_level": risk_level, "message": result})
        except Exception as e:
            self._send(500, {"error": str(e)})

    def _send(self, code, data):
        self.send_response(code)
        self.send_header('Content-Type', 'application/json')
        self.end_headers()
        self.wfile.write(json.dumps(data, ensure_ascii=False).encode('utf-8'))
```

> 💡 핵심은 `from risk_assessment import assess_risk` 이 한 줄이에요. 계산기는 계산만 하고, 서빙 파일이 그걸 **불러다 쓰는** 구조죠.

## 이 구조가 사업화에 주는 이점

1. **위험도 알고리즘 V3로 업그레이드** → `risk_assessment.py`만 수정, 웹 코드는 안 건드림
2. **투자자/의료 자문에게 로직 검증받기** → 계산 파일만 보여주면 됨 (웹 코드와 섞여있지 않아 깔끔)
3. **기능 추가** (예: 리포트 생성, 알림) → `api/`에 파일만 추가하면 됨
4. **pyproject.toml 불필요** → `api/index.py`는 표준 위치라 Vercel이 자동 인식
